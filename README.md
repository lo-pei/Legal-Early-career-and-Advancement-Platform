## 1. 项目概览

LEAP 要做的事只有一件：**把散落在赛事公众号、学校就业网、学长微信里的机会，收成一张按截止日排好的表，并让"报名之后"的组队、协作与院校材料也落在同一个地方。**

法学学生的机会信息从来不缺，缺的是三样东西：**还有多久**、**谁还缺人**、**上一届的东西在哪**。因此项目把三条约束做成了界面能力，而不是写进宣传语：

| 约束 | 界面实现 |
| :--- | :--- |
| **时间是第一维** | 每条机会自带一把 14 天刻度（`.ruler`），填充长度就是剩余天数；剩余 ≤ 7 天时数字与刻度转朱红。默认排序是截止日，不是发布时间 |
| **数字必须能核对** | 提交 = 通过 + 待审 + 打回；应交 = 已交 + 未交；队伍人数 ≤ 上限；分面份数由另外两级已选项现算。`data.js` 末尾有 10 条 `console.assert` 兜底 |
| **一屏只回答一个问题** | 六屏各自只回答一个问题，区块顺序是"对下一个问题的回答"，不是"四个 KPI + 大图表 + 两小图 + 表格"的库存模板 |

### 1.1 一句话边界

| 项 | 结论 |
| :--- | :--- |
| 输入 | 平台自行录入与订阅的机会信息；院校发布的实习计划 |
| 输出 | 可报名的机会清单、队伍招募与任务、往届赛题资料、院系材料台账 |
| 形态 | 桌面为主（1440 侧栏 + 12 列栅格），手机为辅（抽屉 + 底部五项标签栏） |
| 不做什么 | 不做报名代理、不做支付、不接教务系统、不做推荐算法、**不做法律意见** |

## 2. 信息架构

六屏，每屏先回答一个问题，最大的东西就是那个问题的答案：

| 屏 | 它先回答的一个问题 | 最大的东西 | 一个发现 |
| :--- | :--- | :--- | :--- |
| 今天 `index.html` | 这十四天里，哪几件快到期了 | 未来 14 天截止表（12 列满宽） | 4 条在 14 天内，其中 2 条在 7 天内 |
| 机会 `competitions.html` | 还有哪些来得及报名 | 13 条在架信息表 | 绝大多数在 17 天以外，只有两条在逼近 |
| 比赛详情 `competition.html` | 我还来不来得及 | 赛程轨道 + 朱红的「7 天」 | 报名 7 天，书状还有 76 天 |
| 队伍空间 `team.html` | 书状这周谁还差什么 | 任务表（7 项，1 项逾期） | 报名费凭证已逾期 2 天 |
| 资料库 `library.html` | 上一届的书状我能不能看 | 三级路径（赛事 → 年份 → 类型） | 2027 年 Jessup 只有 3 份，模板类全站只有 2 份 |
| 学校端 `school.html` | 哪个班还没交齐 | 按班级的提交率表 | 法学 2303 只有 68.6%，一个人没交等于拖全班 |

主链路：

```text
发现（今天 / 机会）
  → 判断（详情：报名截止还有几天）
  → 组队（详情：哪支队在招、缺什么角色）
  → 协作（队伍空间：任务、成员、材料、时间线）
  → 沉淀（资料库：赛题 / 规则 / 成果 / 模板 / 经验帖）
  → 管理（学校端：应交 / 已交 / 待审 / 打回，按班看）
```

## 3. 设计方向

方向不是凭个人偏好定的，由 `taste-skill` 的 `draw.mjs --app` 发牌产生：**风格 `achromatic-ledger`**（seed 209491491，2026-11-01）。

> 界面骨架没有任何彩色；数字用墨色排；唯一的色相落在"主数据元素"上；除它之外，颜色只出现在一个数字变了的地方。

**理念句**：在这个平台上，**倒计时变成了刻度**——每一行机会都带一把相同的尺，尺的长度就是它离截止还有多远。

一句"竞争对手测试"：把赛氪、法律竞赛公众号、学校就业网代进这句话都不成立——它们没有"还有多久"这件东西，只有发布日期。

### 3.1 两处对发牌结果的主动重绘

| 重绘 | 原发牌 | 改为 | 理由 |
| :--- | :--- | :--- | :--- |
| 壳体 | 图标栏（50–60px 无标签） | 232px 带标签侧栏 | LEAP 有 8 个目的地、中文标签两到四字；无标签图标栏要靠 8 个 tooltip 才认得出，手机折叠成 5 图标会丢掉 3 个入口 |
| 色相 | `#1d5fbf` 蓝 | `#a63a24` 印章朱 | 发牌允许用品牌自身色相（白底 3:1 以上）。这个产品的主数据就是"截止临近"，朱红既是印章色也是紧迫色，比通用 SaaS 蓝更贴主题 |

### 3.2 "给了产品一张脸"的三处

1. **地面取自主题的材料**：`#f4f3f1` 石色（取自纸与卷宗），卡片保持纯白。
2. **朱红只给截止**：剩余 ≤ 7 天时数字与刻度转朱红，其余全部墨色与灰阶。全屏彩色像素 **< 1%**。
3. **数字用等宽**：日期、天数、人数、比率、份数一律 `IBM Plex Mono` + `tabular-nums`，像卷宗的编号列。

**一个只有这个产品有的元素**：截止刻度——84px 的 14 天窗，填充长度为剩余天数，≤ 7 天转朱红；表格里这一列永远在同一条竖线上，扫一眼就知道哪几行在逼近。

## 4. 设计系统

### 4.1 令牌

```css
--ground:#f4f3f1; --surface:#ffffff; --raised:#f7f6f3; --active:#e9e7e1;
--border:#e3e2dc; --rule:#efeee9; --control:#d5d4cd;
--text:#17181a; --muted:#5d6064; --faint:#6c6f73;
--accent:#a63a24; --primary:#1a1b1d;
--positive:#2c6e49; --negative:#a8271f; --warning:#8a5a00;
--radius-card:8px; --radius-control:6px;
--gap:12px; --card-pad:20px; --pad:28px;
--sidebar:232px; --row:44px; --control:32px;
```

状态标签用淡底深字的同色对：绿 `#e3f0e7/#17351f`、红 `#fbedeb/#6d1a15`、琥珀 `#faf1e0/#6b4600`。

**颜色预算**：主色 `#a63a24` 只出现在截止刻度、逾期/临近的数字和一个选中态上。主按钮是近黑 `#1a1b1d`，次级是描边或灰底。没有渐变、没有发光、没有毛玻璃、没有彩色侧栏。

### 4.2 字体

| 角色 | 字体 | 字号 |
| :--- | :--- | :--- |
| 界面文字 | Noto Sans SC（回退 PingFang SC / 微软雅黑） | 24 / 16 / 14 / 13 |
| 数字与编号 | IBM Plex Mono + `tabular-nums`（`body` 全站继承） | 30 / 14 / 13 / 12 |

两种字各一个职责，页面上没有第三种。发牌给的是 Geist / Geist Mono——Geist 没有中文字形，落回系统字体等于"没加载"，所以换成有中文的两款，职责不变。字号阶梯 24 · 16 · 14 · 13 · 12，**没有 11px 以下的字**。

### 4.3 栅格

画布 1440 − 232 侧栏 − 2×28 内边距 = **1152**；12 列、12px 沟槽 → 单列 85。

`12×85 + 11×12 = 1020 + 132 = 1152`

常用切分：`8+4` = 764+376，`7+5` = 667+473，`4+4+4` = 376×3，均带 12px 沟槽，左右边距相等。

**同一行的卡片必须同底**：要么行数相同，要么给短的卡片 `.stretch` 并把**动作**（不是说明文字）钉到底部。不允许"卡片比邻居短一截"或"卡里空出一条带子"。

### 4.4 组件规则

| 组件 | 规则 |
| :--- | :--- |
| **面板** | 白底、1px `#e3e2dc` 边、8px 圆角、20px 内边距。无阴影（只有浮层才有） |
| **KPI 条** | 一张卡用 1px 竖线分成等宽格，标签在上、数字在下（30px 等宽），**无图标、无迷你趋势线** |
| **表格** | 12px 灰色表头，行分隔线 1px，无斑马纹、无表头底带；数字右对齐、等宽；状态列最右 |
| **状态标签** | 22px 高，淡底深字；"进行中"用实底中性、"待开始"用描边——**填充代表它在动** |
| **按钮** | 一屏只有一个近黑实底主按钮，其余描边或纯文字 |
| **动效** | 只有反馈（按下位移 1px、hover 换底、焦点环）；应用界面不做入场动画 |

## 5. 关键交互

四处设计决定都写明了"为什么不是另一种做法"：

### 5.1 截止刻度与 14 天窗

`ruler(o)` 只画 14 天内的相对位置：`pct = d > 14 ? 0 : d / 14`。**超过 14 天的条目刻度为空，不是满格**——窗只有 14 天，画满格会让人误以为"很紧"。同一列在所有表格里落在同一条竖线上，所以能竖着比较。

### 5.2 资料库三级路径

路径为 **赛事 → 年份 → 类型**。分面份数**按"另外两级已选"现算**，不是静态数字：点 `Jessup` 后 21 → 8，再点 `2027 年` → 3，同时 `成果 / 模板 / 经验帖` 因 0 份自动置灰且不可点——**路径里不会出现死路**。

第三级原本打算做"赛道（中/英）"，查数据后否掉：除 ICC 分中文赛与英文赛，其余四个赛事只有一个语言值，做成一级会让用户点进去发现选项没有变窄。赛道降为行内属性（`PDF · 41 页 · 英文`），第三级换成学生真会拿来筛的**类型**。

**授权是第一等字段，不是附注**：每份资料带 `public / team / index / pending` 四态（示例数据 13 / 5 / 1 / 2），决定行末是「获取」还是「—」。仅登记题录的资料照样出现，因为"知道它存在但拿不到"本身是有效信息。

### 5.3 「仅按日期」密度视图

第一版做错了，值得记下来：把日期做成分组标题后，13 条里每条都各自成组，行数反而翻倍，**比表格更长**——那不是紧凑，是更松散。改为**三列网格：日期轨 | 标题 | 剩余**，同一截止日只写一次日期，剩余天数回到右侧数字列，一项一行。

这也是对"按日期排序"的诚实处理：排序键应该变成行首的身份，而不是继续占一列。

### 5.4 手机端

侧栏折成抽屉 + 底部五项标签栏；表格改为"**标题 + 来源行 + 带标签的数字**"，刻度条隐藏（数字已经说了），**不做横向滚动**。资料库三个分面列换成三个原生下拉（选项里带份数），面包屑隐藏——下拉本身已经说明了路径，留着就是同一个信息说两遍。

## 6. 快速开始

原型是纯静态页面，无 npm、无构建、无 CDN 依赖。因涉及字体与 `file://` 下的脚本加载，建议起一个本地服务：

```bash
cd design/prototype
python -m http.server 8000
```

| 地址 | 看什么 |
| :--- | :--- |
| `http://localhost:8000/index.html` | 今天：未来 14 天截止表 + 我的队伍 / 新机会 / 待办 |
| `http://localhost:8000/competitions.html` | 机会：13 条在架信息；试右上角 `详细 ↔ 仅按日期` |
| `http://localhost:8000/competition.html` | 详情：赛程轨道、组队专区、资料入口 |
| `http://localhost:8000/team.html` | 队伍空间：任务表、成员、材料清单 |
| `http://localhost:8000/library.html` | 资料库：点 `Jessup` → `2027 年`，看份数与置灰联动 |
| `http://localhost:8000/school.html` | 学校端：按班级提交率与审核队列 |

也可以直接双击 `index.html`，但字体可能回退到系统字体，版面会略有出入。

## 7. 质量保障

三套检查都是可复跑的，不是一次性人工确认：

```bash
# 1) 源码规则（taste-skill 的 app-screens 硬规则）
node <taste-skill>/scripts/lint.mjs --app .

# 2) 真实浏览器度量（1440 / 768 / 390），含溢出、同底、对齐、小字号
node <taste-skill>/scripts/inspect.mjs --app index.html --widths 1440

# 3) 渲染后反模式扫描（62 条规则，含对比度）
npx impeccable detect http://localhost:8000/index.html --json
```

| 保障项 | 机制 | 结果 |
| :--- | :--- | :--- |
| **浏览器度量** | `inspect.mjs --app` 逐屏逐宽度实测，不靠肉眼 | 六屏 × 3 宽度 = **18 次，0 FAIL / 0 WARN** |
| **反模式扫描** | `impeccable detect` 对渲染后的 DOM 扫描（含对比度与小字） | 六屏 **0 条反模式** |
| **源码规则** | `lint.mjs --app` | **0 FAIL / 23 WARN**，四类均有理由（见下） |
| **数据自洽** | `data.js` 末尾 10 条 `console.assert` | 提交 = 通过 + 待审 + 打回；应交 = 已交 + 未交；队伍人数 ≤ 上限；资料不重复；待审核的都是投稿 |
| **交互实测** | CDP 脚本点击后读 DOM，不靠截图判断 | 资料库 `Jessup` → 8 份；`+2027 年` → 3 份且三项置灰 |
| **横向溢出** | 逐元素比对 `getBoundingClientRect().right` 与 `clientWidth` | 三宽度均无元素越界 |

23 条 WARN 的四类理由：`mono` 17 处（等宽是这个风格的既定决定）、`shadow` 4 处（行首"我的"竖线、赛程节点环、抽屉遮罩，都不是静止卡片投影）、`numbering` 1 处（`fmtDate` 的零填充，是日期格式化不是 01/02/03 编号）、`em-dash` 1 处（日期区间与空值占位，中文排版的正确用法）。

### 7.1 只有看渲染结果才会发现的缺陷

测量全绿不等于没问题。以下六处都是**截了图、放大看**才现形的：

| 缺陷 | 怎么发现的 | 处理 |
| :--- | :--- | :--- |
| 面包屑只剩"资料库"一个孤立词 | 1440 截图 | 改常驻四段，未选层级浅灰占位 |
| 移动端出现「获取 获取」 | 390 二倍放大截图 | 去掉该单元的重复标签 |
| 「更新」列 `10.28` 与 `2026.04` 混排 | 1440 截图 | 统一为 `YYYY.MM.DD` |
| `119 天后` 在 46px 列里折成两行 | 390 截图 | `.due` 加 `nowrap`，列宽 52px |
| 手机标题截断到无法辨认 | 390 放大截图 | 日期视图允许两行 |
| 首页「我的队伍」把「衡平」队写了两遍 | 首页截图 | 改为"2 份入队申请待审核"，数字由 `TEAMS` 推导 |

| 资料库 `library.html` | 🟡 只做"取" | 三级浏览与授权态可用；**搜索框与投稿上传未做** |
| 学校端 `school.html` | 🟡 单计划 | 五个班的提交率与审核队列；**跨学期对比未做** |
| 手机端 | ✅ 六屏三宽度 | 抽屉 + 底部五项、表格堆叠、日期视图 |
| 求职中心 | 🟡 复用 | 仅复用机会列表的 `?kind=job`，**无独立淘选** |
| 后端 / 账号 / 支付 | ❌ 未开始 | 全部交互在浏览器内用示例数据完成 |

> **已验证**：三套检查全部可复跑、六屏三宽度 0 FAIL、数据 10 条断言通过、交互点击实测。
> **未验证**：真实数据量下的表现（21 份资料翻得完，200 份不行）、真实用户可用性测试、跨浏览器（仅 Chromium）。
> **不要把"测量通过"当成"产品可用"。**

## 10. 已知不足

| 范畴 | 不足 |
| :--- | :--- |
| **资料库规模** | 没有搜索框。21 份可以靠三级路径翻完，两百份就不行。下一步应在路径行右端加只匹配标题与来源的即时搜索，并让分面计数随结果重算 |
| **投稿闭环** | `投稿一份` 是死链接，缺上传、版权声明勾选、作者侧审核状态视图 |
| **卡片同底** | 首页底部三卡靠"每卡四行"维持同底，内容一变就要重新配平；更稳的做法是改成一张分栏卡 |
| **赛程是阶段列表** | 不是真实时间轴。要做真时间轴需按日期比例定位并处理标签碰撞（10.12 与 11.08 只差 5%） |
| **手机滚动长度** | 日期视图 13 条约 1400px 高，仍要滚很久；真正需要的是"本周 / 下周 / 本月"分段锚点 |
| **桌面冗余切换** | 「仅按日期」在桌面上收益不大（表格本来就够密），可考虑 ≥861px 时隐藏，少一个决定 |
| **求职中心** | 仍复用机会筛选，没有"按届别 / 按城市 / 按留用可能"的淘选 |
| **学校端** | 只画了单个实习计划，跨学期对比与批量催交的结果反馈未画 |
| **示例数据** | 13 条机会（比赛 6 / 征文 3 / 求职 4）、21 份资料、3 支队伍、7 项任务、5 个班级，全部为看密度而编，人名与机构名需替换或脱敏 |

## 12. 下一步

按投入产出排，前两项决定这套设计能不能撑到真实数据量：

1. **资料库搜索**（小投入）— 标题 + 来源即时匹配，分面计数随结果重算。没有它，资料库只能停在"demo 量级"。
2. **"本周 / 下周 / 本月"分段锚点**（小投入）— 解决手机上日期视图滚不完的问题，比继续压行高有效。
3. **投稿闭环**（中投入）— 上传、版权声明、作者侧状态。这是资料库从"取"变成"有东西可取"的前提。
4. **赛程真时间轴**（中投入）— 需要先解标签碰撞，否则宁可保持阶段列表。
5. **后端与账号**（大投入）— 计划书里已有接口与数据模型草案，但当前所有数据都是 `data.js` 里的常量。

接手时先读 [`design/DESIGN.md`](design/DESIGN.md) §9，那里列的是**这套设计自己承认的短板**，不是待办清单的美化版。
