# DESIGN.md — LEAP 设计系统

> 方法：`taste-skill`（app-screens 规则 + `draw.mjs --app` 方向发牌 + `lint.mjs` / `inspect.mjs` 关卡）
> 与 `impeccable`（62 条反模式检测器）两套规则同时满足。
> 原型目录：`design/prototype/`　评审截图：`design/review/`

## 1. 方向

**风格：`achromatic-ledger`**（seed 209491491，2026-11-01 发牌）

> 界面骨架没有任何彩色；数字用墨色排；唯一的色相落在"主数据元素"上；除它之外，颜色只出现在一个数字变了的地方。

**理念句**

> 在这个平台上，**倒计时**变成了**刻度**——每一行机会都带一把相同的尺，尺的长度就是它离截止还有多远。

一句"竞争对手测试"：把赛氪、法律竞赛公众号、学校就业网代进这句话，都不成立——它们没有"还有多久"这件东西，只有发布日期。

**两处重绘，各有理由**

| 重绘 | 原发牌 | 改为 | 理由 |
| :--- | :--- | :--- | :--- |
| 壳体 | 图标栏（50–60px 无标签） | 232px 带标签侧栏 | LEAP 有 8 个目的地，中文标签两到四字；无标签图标栏要靠 8 个 tooltip 才认得出，且手机折叠成 5 图标会丢掉 3 个入口 |
| 色相 | `#1d5fbf` 蓝 | `#a63a24` 印章朱 | 发牌允许"品牌自身色相（白底 3:1 以上）"。这个产品的主数据就是"截止临近"，朱红既是印章色也是紧迫色，比通用 SaaS 蓝更贴主题 |

**"给了产品一张脸"的三处（缺一则像一套皮肤）**

1. **地面取自主题的材料**：`#f4f3f1` 石色（发牌给出的三个"取脸"方式之一），卡片保持纯白。
2. **朱红只给截止**：剩余天数 ≤ 7 时数字与刻度转朱红；其余全部墨色与灰阶。全屏彩色像素 < 1%。
3. **数字用等宽**：日期、天数、人数、比率、案号式编号一律 `IBM Plex Mono` 并 `tabular-nums`，像卷宗的编号列。

**一个只有这个产品有的元素**：截止刻度（`.ruler`）——84px 的 14 天窗，填充长度为剩余天数，≤7 天转朱红；表格里这一列永远在同一条竖线上，扫一眼就知道哪几行在逼近。

状态标签用淡底深字的同色对：绿 `#e3f0e7/#17351f`、红 `#fbedeb/#6d1a15`、琥珀 `#faf1e0/#6b4600`。

**颜色预算**：主色 `#a63a24` 只出现在截止刻度、逾期/临近的数字与一个选中态上。主按钮是近黑（`#1a1b1d`），次级是描边或灰底。没有渐变、没有发光、没有毛玻璃、没有彩色侧栏。

## 3. 字体

| 角色 | 字体 | 字号 |
| :--- | :--- | :--- |
| 界面文字 | Noto Sans SC（回退 PingFang SC / 微软雅黑） | 24 / 16 / 14 / 13 |
| 数字与编号 | IBM Plex Mono + `tabular-nums`（`body` 上已全站继承） | 30 / 14 / 13 / 12 |

两种字各一个职责。发牌给的是 Geist / Geist Mono——Geist 没有中文字形，落回系统字体就等于"没加载"，所以换成有中文的两款，职责不变（正文 / 数字）。页面上没有第三种字体，标题里也不做斜体或彩色强调。

字号阶梯：24（页标题）· 16（卡片标题）· 14（正文、表格、导航）· 13（辅助行、meta）· 12（标签、单位）。没有 11px 以下的字。

## 4. 栅格

画布 1440 − 232 侧栏 − 2×28 内边距 = **1152**；12 列、12px 沟槽 → 单列 85。
`12×85 + 11×12 = 1020 + 132 = 1152`。
常用切分：`8+4` = 764+376，`7+5` = 667+473，`4+4+4` = 376×3，均带 12px 沟槽，左右边距相等，内容贴到画布两边。

**同一行的卡片必须同底**：要么行数相同（每卡四行），要么给短的卡片 `.stretch` 并把**动作**（不是说明文字）钉到底部。不允许"卡片比邻居短一截"或"卡里空出一条带子"。

## 5. 组件

- **面板**：白底、1px `#e3e2dc` 边、8px 圆角、20px 内边距。无阴影（只有浮层才有）。
- **KPI 条**：一张卡用 1px 竖线分成等宽格，标签在上、数字在下（30px 等宽），无图标、无迷你趋势线。
- **表格**：12px 灰色表头，行分隔线一行 1px，无斑马纹、无表头底带；数字右对齐、等宽；状态列最右。
- **状态标签**：22px 高，淡底深字；"进行中"用实底中性，"待开始"用描边——**填充代表它在动**。
- **截止刻度**：见 §1。超过 14 天的条目刻度为空（不是满格），因为窗只有 14 天。
- **赛程轨道**：四段等分，节点圆点，已过为实心墨、当前为朱红、未到为空心；连接线止于末点。它是**阶段列表**不是时间轴——日期跨度并不均等，所以不画比例位置。
- **人员**：24px 头像，首字 + 各自极淡的色底（身份，不进图表图例）。
- **按钮**：一屏只有一个近黑实底主按钮；其余描边或纯文字。
- **动效**：只有反馈（按下位移 1px、hover 换底、焦点环），应用界面不做入场动画。
- **三级路径**（资料库）：赛事 / 年份 / 类型横排三列，行高 30px，选中行用 `--active` 底（与侧栏"当前页"同一语义，不新造一种选中态），每行右端是等宽份数。份数按"另外两级已选"计算，所以**点灰色选项一定不会点出空页**。手机换成三个原生下拉，选项里带份数，等级关系由标签"赛事 / 年份 / 类型"承担。
- **面包屑路径**：常驻四段（资料库 › 全部赛事 › 全部年份 › 全部类型）。未选层级是浅灰占位，已选层级可点回上一层，最深一层是墨色终点。手机隐藏——三个下拉本身已经说明了路径。
- **日期刻度轨**（机会页「仅按日期」）：日期与星期在左轨，同一截止日只在第一条出现一次；剩余天数回到右侧数字列，保持"天数永远在同一竖线上"。一项一行，手机上标题最多两行。
- **密度切换**：`详细 / 仅按日期` 两个按钮的分段控件，放在筛选行右端（它与"按截止日升序"是同一类决定：怎么排、怎么显示）。

## 6. 六屏

| 屏 | 它先回答的一个问题 | 最大的东西 | 一个发现 |
| :--- | :--- | :--- | :--- |
| 今天 `index.html` | 这十四天里，哪几件快到期了 | 未来 14 天截止表（12 列满宽） | 4 条在 14 天内，其中 2 条在 7 天内 |
| 机会 `competitions.html` | 还有哪些来得及报名 | 13 条在架信息表 | 绝大多数在 17 天以外，只有两条在逼近 |
| 比赛详情 `competition.html` | 我还来不来得及 | 赛程轨道 + 朱红的「7 天」 | 报名 7 天，书状还有 76 天 |
| 队伍空间 `team.html` | 书状这周谁还差什么 | 任务表（5 项，1 项逾期） | 报名费凭证已逾期 2 天 |
| 资料库 `library.html` | 上一届的书状我能不能看 | 三级路径（赛事 → 年份 → 类型） | 2027 年 Jessup 只有 3 份，模板类全站只有 2 份 |
| 学校端 `school.html` | 哪个班还没交齐 | 按班级的提交率表 | 法学 2303 只有 68.6%，一个人没交等于拖全班 |

每屏的区块都是对下一个问题的回答，没有"四个 KPI + 大图表 + 两小图 + 表格"的库存顺序。

**资料库为什么不把"赛道"做成一级**：原来打算做赛事 / 年份 / 赛道三级。查下来除 ICC 分中文赛与英文赛，其余四个赛事只有一个语言值——做成一级，用户点进去会发现选项没有变窄。所以赛道降级成行内属性（`PDF · 41 页 · 英文`），第三级换成**类型**（赛题 / 规则 / 成果 / 模板 / 经验帖），那是学生真正会拿来筛的东西。

**授权是第一等字段，不是附注**：每份资料都带 `public / team / index / pending` 四态，决定行末是「获取」还是「—」。仅登记题录的资料照样出现，因为"知道它存在但拿不到"本身是有效信息，比假装没有更有用。

## 7. 规则（会被检查的部分）

1. 数字从行里算出来，不单独写死：提交 = 通过 + 待审 + 打回；应交 = 已交 + 未交；队伍人数 ≤ 上限。`data.js` 末尾有十条 `console.assert`。
2. 同一事实只有一处变量：赛程里的"7 天"与标题下的"报名截止 11.08"来自同一个日期。
3. 相对数字必须说明对谁而言："比上周新增 9 份""距今 7 天""已逾期 2 天"。
4. 零就是零，缺失是一个灰色破折号（已完成的任务剩余列、不可获取的资料都显示 `—`）。
5. 表格对齐：日期右对齐、天数右对齐、费率右对齐；刻度列永远同一条竖线。
6. 手机：侧栏折成抽屉 + 底部五项标签栏；表格改为"标题 + 来源行 + 带标签的数字"，刻度条隐藏（数字已经说了），不做横向滚动。
7. 一屏一个近黑主按钮；其余动作是描边或文字链接。
8. 分面数字是"点进去还能看到几份"，由另外两级已选项现算；为 0 的选项置灰且不可点，路径里不会出现死路。
9. 按日期看时，日期是行首的身份而不是一列：同一截止日只写一次，剩余天数仍在右侧数字列对齐。
10. 日期刻度只在 14 天窗内有意义：超过 14 天的条目刻度为空，不是满格。

## 8. 校验

- `lint.mjs --app`：**0 FAIL，23 条 WARN**，分四类且每条都有理由——`mono` 17 处（等宽是这个风格的既定决定：日期、天数、份数、比率一律 Plex Mono）；`shadow` 4 处（行首"我的"竖线、赛程节点环、抽屉遮罩、日期轨的"我的"竖线，都不是静止卡片的投影）；`numbering` 1 处（`fmtDate` 的零填充，是日期格式化不是 01/02/03 编号）；`em-dash` 1 处（3 个日期区间与 2 个空值占位，中文排版的正确用法）。
- `inspect.mjs --app`：六屏 × 1440 / 768 / 390 = **18 次，全部 0 FAIL、0 WARN**。
- `impeccable detect`（渲染后再扫，含对比度与小字规则）：六屏 **0 条反模式**。
- 交互：资料库点 `Jessup` → 路径变 `资料库 › Jessup › 全部年份 › 全部类型`，份数 21 → 8；再点 `2027 年` → 3 份，且 `成果 / 模板 / 经验帖` 三项因 0 份自动置灰。机会页 `详细 ↔ 仅按日期` 切换后行数由 13 行表格变为 13 行日期轨。

## 9. 已知不足

1. 首页底部三卡靠"每卡四行"维持同底，内容一变就要重新配平；更稳的做法是把三卡改成一张分栏卡。
2. 赛程是阶段列表而非真实时间轴。要做真时间轴，需要按日期比例定位并处理标签碰撞（10.12 与 11.08 只差 5%）。
3. **资料库没有搜索框**。21 份可以靠三级路径翻完，两百份就不行；下一步应在路径行右端加一个只匹配标题与来源的即时搜索，并保持分面计数随搜索结果重算。
4. 资料库只做了"取"，没做"交"：`投稿一份` 目前是死链接，缺上传、版权声明勾选、审核状态的作者视图。
5. 「仅按日期」在桌面上也开着，但它在桌面上的收益不大（表格本来就够密）；如果只服务手机，可以在 ≥861px 时隐藏这个切换，减少一个决定。
6. 手机上日期轨的标题允许两行后，13 条约 1400px 高，仍然要滚很久；真正需要的是"本周 / 下周 / 本月"的分段锚点。
7. 求职中心仍复用「机会」列表的筛选（`?kind=job`），没有单独的"按届别 / 按城市 / 按留用可能"的淘选。
8. 学校端只画了单个实习计划，跨学期对比与批量催交的结果反馈没有画。
