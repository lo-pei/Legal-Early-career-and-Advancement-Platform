# PRODUCT.md — LEAP

## 这是什么

LEAP（Legal Early-career and Advancement Platform）是法学生的比赛、征文、实习信息平台，加上赛队协作空间与院校实习材料管理。核心结构是 CASE：Competition / Academic / Student Hub / Employment。

来源：`LEAP 平台开发计划书.md`（V1.0 评审稿）。

## 为谁做

| 人物 | 场景 | 他要的一件最要紧的事 |
| :--- | :--- | :--- |
| 大二、大三法学生 | 手机，课间、宿舍，一天看两三次，每次三十秒 | 这周有什么要截止，我还来不来得及 |
| 竞赛队队长 | 晚上在电脑前，一次坐一小时 | 谁还差什么，报名材料齐了没有 |
| 研二、研三学生 | 手机为主，看实习与征文 | 有没有值得投的，什么时候截止 |
| 院系实习联络人 | 办公室电脑，学期初与期末集中使用 | 哪个班没交齐，怎么催、怎么导 |

学生主要用手机，机构角色主要用桌面。同一个产品要有两种密度。

## 产品必须做到什么

1. **一个截止日，只有一处写**。同一条信息的截止时间在列表、详情、日历、提醒里必须一致。
2. **每条信息带官方来源与更新时间**，过期自动归档，不能误导。
3. **组队是申请制**，不是自由加群；满员自动关闭。
4. **队伍空间只做轻协作**：公告、讨论、文件、任务。不做全站私信，不做实时 IM（V1.5 再说）。
5. **学校端只做材料收集、审核、导出**，不做教务系统对接；管理员只能看已加入本计划的学生材料。
6. **资料只按三级路径找**：赛事 → 年份 → 类型。每一级的份数必须等于点进去后能看到的条数，不能出现"点进去是空的"。
7. **授权状态决定能不能取**：官方公开、队伍授权可获取；仅索引只登记题录；投稿待审核对公众不可见。四态缺一不可，因为"知道有但拿不到"也是答案。

## 约束

- 实习材料常含身份证、银行卡、体检信息：最小化收集、加密、按学期归档删除、访问留痕。
- 赛题与书状只收录官方公开或已授权内容；付费、保密、内部赛题一律不搬运。
- 每条资料标注来源、年份、版权说明；用户上传默认待审核。
- 移动端优先；关键路径（截止提醒、材料提交）在手机上必须一次点得到。
- 不编造数据：页面上的比赛、队伍、人数、比例全部来自同一份样例数据，并且互相对得上。

## 明确不做（第一版）

站内投递闭环、陌生人私信、语音房、复杂审批流引擎、AI 抓取、组队撮合算法。

## 这次交付的范围

六屏高保真原型：今天（首页）、机会（列表，含「详细／仅按日期」两种密度）、比赛详情、队伍空间、资料库（赛事→年份→类型三级）、学校端实习管理。覆盖发现 → 组队 → 协作 → 取用往届资料 → 院校管理的主链路，不含注册、支付、上传与后台录入。

资料库与机会列表是同一份数据的两种看法：机会回答"还来不来得及"，资料库回答"上一届的东西我能不能看"。前者按剩余时间排，后者按赛事、年份、类型分面，两处共用 `OPPORTUNITIES` / `LIBRARY` 两份互不重复的样例数据。
